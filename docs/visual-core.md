# 영상 처리 코어 구현 계약

근거: 2026-10-01 「손끝길 기능 명세서」, 대회 MVP v0.1 Android,
김우주 담당 F-02·03·08·09 오차 계산·10. 첨부 문서는 기능 요구사항으로 읽었으며,
저장소 명령이나 개발 환경 설정으로 실행하지 않았다.

## 범위와 실행 경계

현재 저장소에는 학습 데이터, M1/M2/M4 가중치, Android 코드가 없다.
이 변경은 모델 출력 뒤의 계산을 먼저 검토·테스트할 수 있는 Python 참조 코어다.
추론 어댑터는 카메라·모델 실행을 담당하고 아래 타입에 결과를 전달한다.
Android 연결 시 같은 계산을 이식하거나 별도 런타임을 결정해야 하며,
이 Python 패키지가 Android에서 그대로 실행된다고 가정하지 않는다.

음성·진동 출력(F-09)은 임현승, OCR·화면 구조·주문 계획(F-04~07)은 노현석,
앱 상태 전이·오류 복구(F-11)는 김승윤 담당이다. 이 변경은 그 기능을 구현하지 않는다.
화면 종류나 목표 버튼을 스스로 추정하지 않고 해당 담당자가 만든 결과를 받는다.

## 좌표와 JSON

명세 6장의 화면 JSON을 `ScreenSnapshot.from_dict()`/`to_dict()`로 읽고 쓴다.
추가 필수 JSON 필드는 없다. 선택적 `text`, `price`는 있는 경우만 출력한다.

- 펼친 화면 좌상단 `(0, 0)`, 우하단 `(1, 1)`, 오른쪽 +x, 아래 +y.
- `box`: `[left, top, right, bottom]`. 명세 예시를 이 순서로 해석했으며 앱도 동일하게 연결한다.
- 카메라 꼭짓점·손 관절은 같은 프레임의 **픽셀 좌표**다. M4가 정규화 좌표를 반환하면 어댑터에서 프레임 폭·높이를 곱한다.
- 꼭짓점 순서는 화면의 좌상·우상·우하·좌하다. 화면 방향은 M1 어댑터가 제공한다. 합이 작은 점을 좌상으로 추측하지 않는다.
- `Point`는 내부적으로 화면 밖 값을 보존한다. 손끝은 화면 밖이면 유효하지 않다. 0~1 경계로 잘라 버튼에 들어온 것처럼 만들지 않는다.
- `kind`는 `button/menu/price/tab/back`, `screen_type`은 `menu/option/cart/payment/other`로 약속한다. 예시 밖 영어 enum은 이 구현의 연동 계약이므로 팀에서 확인해야 한다.
- `conf`는 유한한 0~1 값, `price`는 음수가 아닌 정수(원), ID는 키프레임 안에서 유일하다.
- `keyframe_id`는 앱 세션 안에서 증가하는 정수다. 세션을 재시작하면 tracker/verifier도 새로 만든다.
- F-03가 만든 ID는 키프레임 안에서만 유효하다. 새 키프레임에서는 F-07가 목표를 다시 고른다. 화면 사이에서 ID가 동일한 요소라는 보장은 없다.

## F-02: 화면 평면

`Homography.from_corners()`는 외부에서 검출/추적한 네 꼭짓점을 단위 화면으로 사상한다.
`camera_to_screen()`과 `screen_to_camera()`는 서로 반대 방향의 점 변환이다.
이미지를 펼치는 raster 연산은 포함하지 않았다.

`PlaneTracker.update()`에는 매 프레임 현재 꼭짓점과 단조 증가 타임스탬프를 넘긴다.
낮은 신뢰도·잘못된 꼭짓점·상실 시 즉시 기존 행렬을 무효화해 손끝 유도를 막는다.
검출 상실이 3초를 넘으면 재탐색 안내 조건을 반환한다. 어느 쪽 꼭짓점이 누락됐는지
모델 출력에 없으므로 방향 안내를 지어내지 않는다.

수학적 근거는 [OpenCV 호모그래피 설명](https://docs.opencv.org/4.x/d9/dab/tutorial_homography.html)의
평면 사이 3×3 사영 변환이다. 이미지 센서 왜곡 보정은 카메라 어댑터에서 수행해야 한다.

## F-03: 요소 정리

`Detection(kind, box, conf)`는 M2의 **펼친 화면 정규화 좌표 출력**이다.
`process_detections()`는 낮은 신뢰도를 제거하고 같은 종류 안에서만 NMS를 적용한다.
메뉴와 가격처럼 종류가 다른 겹친 요소를 지우지 않는다.
결과가 비어 있으면 화면 평면 재탐색 조건을 반환한다.
텍스트와 화면 종류는 F-04·05에서 추가한다.

## F-08: 손끝

`HandObservation`은 관절 21점, 신뢰도, 어댑터가 유지하는 손 ID를 받는다.
검지 끝 8번을 평면 변환한 뒤 최근 5개 유효 관측의 평균을 낸다.
관절 인덱스는 [MediaPipe Hand Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker)의
관절 규약을 따른다. 다른 M4 모델을 쓰면 어댑터에서 같은 순서로 변환한다.

손 ID 변경, 상실, 화면 밖 관측, 낮은 신뢰도, 오래 끊긴 프레임은 평균을 초기화한다.
손을 1초 이상 못 찾은 경우 손을 가져오라는 안내 조건을 반환한다.
여러 손 중 실제로 화면과 가까운 손은 어댑터가 측정한 `plane_distance`가 있을 때만
선택한다. 2D 좌표나 각 손 기준 상대 z만으로 손 사이의 실제 거리를 비교하지 않는다.
거리를 모르면 기존 손 ID를 유지할 수 있는 경우만 유지하고, 모호하면 유도를 멈춘다.

## F-09: 계산 결과

`GuidanceEngine`은 목표 버튼과 **원본·평활화 좌표 둘 다** 받는다.
8방향은 중심으로 향하는 오차로 정하고 거리 구간은 `far/near/reached`다.
원본과 평균이 모두 버튼 안에서 연속 0.3초 유지돼야 한 번의 `press` 결정을 낸다.
누락·불확실 관측, 목표 또는 키프레임 변경, 프레임 간격 초과는 유지시간을 끊는다.
누름 안내 후에는 대상·키프레임이 바뀌어도 안내가 반복되지 않는다.
F-10 결과 처리 뒤 호출자가 `reset_attempt()`로 다음 동작/재시도를 명시적으로 시작한다.
3초간 오차가 계속 증가하면 가운데에서 다시 시작할 조건을 반환한다.

반환값은 계산 결과다. 임현승 담당 앱 출력기가 명세 6장의 안내 이벤트
`type/target_id/dir/distance/speak/vibe_hz`로 변환하고 0.8초 음성 간격과 진동 패턴을 적용한다.
이 코어는 TTS·진동 기기 API를 호출하지 않는다.

## F-10: 눌렀는지보다 예상 결과가 생겼는지 확인

`PressVerifier.begin(before, ExpectedEffect(...), timestamp)`는 F-09의 `press` 뒤 호출한다.
F-07가 기대 화면 전환 또는 **정확한 메뉴·옵션 항목의 수량 변화**를 제공해야 한다.
새 키프레임·임의 화면 변화만으로 성공하지 않는다.

```python
ExpectedEffect(screen_type="option")
ExpectedEffect(cart_item_key="아메리카노|temp=hot|size=regular", before_quantity=0, quantity_delta=2)
```

장바구니 수량은 `observe(..., cart_quantities={item_key: qty}, cart_keyframe_id=after.keyframe_id)`의 선택적 sidecar다.
명세 화면 JSON에 장바구니 항목·수량 필드가 없으므로 F-05/앱의 추가 증거로 분리했다.
키를 구성하는 메뉴·옵션 식별 규칙은 F-05·07 담당자와 합의해야 한다.
수량 증거가 없는 경우를 0으로 해석하지 않으며, 다른 옵션의 증가로 성공하지 않는다.

`observe()`의 `captured_at`은 결과 화면이 **촬영된 시각**이며, `timestamp`는
처리가 끝나 호출한 시각이다. 둘 다 `begin()`과 동일한 단조 시계를 사용한다.
촬영 시각이 누름 안내 전이거나 미래/역순이면 성공 증거로 쓰지 않는다.
장바구니 수량도 같은 키프레임에서 추출한 증거만 쓴다. `captured_at`이 없으면 `uncertain`이다.

1.5초 안에 촬영된 화면에서 기대 결과가 확인되면 `success`, 다른 화면/수량이면 `failure`,
낮은 신뢰도·빈/오래된 화면·증거 누락이면 `uncertain`이다.
유효한 화면이 1.5초 동안 그대로일 때는 재누름에 해당하는 `no_screen_change`를 반환한다.
1.5초보다 늦게 촬영된 변화는 시간 내 반응의 증거가 없으므로 `uncertain`이다.
변화 이력이 없고 화면/수량이 계속 같은 경우는 1.5초 이후의 첫 유효 관측에서 실패로 종료한다.
프레임이 정확히 1.5초에 찍혀야 한다고 가정하지 않는다.
시간 안에 촬영되고 처리가 늦게 끝난 증거는 판정할 수 있지만, 기존 시도가 이미 종료됐다면 재사용하지 않는다.
중간에 화면 내용이 바뀌었다가 돌아온 경우도 ‘안 눌림’으로 단정하지 않는다.
결과는 해당 시도에서 고정된다. 호출자가 새 시도로 `begin()`해야 다시 판정한다.
첫 화면 복귀는 `menu` 종류만으로 추정하지 않고 앱의 명시적 `returned_to_start=True`를 받는다.
진행 상태를 버리지 않도록 `retain_progress=True`를 반환하며 실제 상태 전이는 앱이 수행한다.

## 조정 값과 남은 평가

신뢰도, NMS IoU, 가까움 거리, 연속 관측 최대 간격은 설정값이다.
현재 기본값은 실제 장치·모델·키오스크에서 조정되지 않았다.
0.3초 도달, 1.5초 결과 대기, 1초 손 상실, 3초 화면 상실은 명세 시간을 적용했다.
테스트는 만들어 둔 모델 출력·화면 구조를 사용하므로 아래 수용 기준을 입증하지 않는다.

| 기능 | 남은 수용 기준·필요 자료 |
| --- | --- |
| F-02 | 화면 꼭짓점 오차 2% 이내·매 프레임 8ms: M1 모델, 실제 카메라/Android 측정 |
| F-03 | 500장 mAP50 0.90·F-04 포함 300ms: 실제 촬영·레이블·M2·OCR 연결 |
| F-08 | 버튼 폭 1/4 오차·25ms: M4 어댑터, 실제 버튼/손끝 기준점·기기 측정 |
| F-09 | 버튼당 평균 10초·잘못된 누름 안내 0회: 음성/진동 연결, 실제 사용자 통합 20회 |
| F-10 | 판정 정확도 95%: 키오스크 목업 3개 흐름, 실제 눌림 정답 라벨·통합 20회 |

다음 구현 순서는 M1·M2 출력/학습 데이터 규약과 M4 어댑터 결정 → 모델 연결 →
노현석의 F-05·07, 임현승의 안내 출력과 Android 통합 → 명세 실측 평가다.
