# Android 화면 메뉴 매칭

`android/sonkkeut-native/.../ScreenMenuResolver.kt`는 음성으로 확인한 메뉴와 화면 OCR을 같은 `MenuDocument.id`로 연결한다. 순수 Kotlin으로 실행되며 AI 서버나 LLM이 필요하지 않다.

입력은 매장 카탈로그, 목표 메뉴 ID, 검출된 요소 ID/종류/글자/정규화 좌표/읽기 가능 여부다. 출력 상태는 `FOUND`, `CONFIRM`, `AMBIGUOUS`, `MISSING`이다. `FOUND`도 버튼 검출과 프레임 검사는 호출 앱의 책임이다.

- 정식 이름 우선, 등록 별칭은 동일 상품으로 인정.
- Unicode·공백·원화 가격 정규화.
- 네 글자 이상 이름의 한 글자 손상은 확인 후보로만 반환.
- 디카페인·제로·온도·크기·세트 구분어가 달라진 오탈자 후보는 제외.
- 기존 버튼 영역에 완전히 들어온 2~3줄만 결합하고 그 버튼 ID를 유지. 인접 카드 결합이나 새 ID/좌표 생성 없음.
- 가까운 경쟁 상품과 중복 위치는 선택 보류. 품절 상품의 정식 이름을 다른 상품의 별칭으로 대체하지 않음.
- 관련 표현(`relatedTerms`)은 물리 버튼 동일성의 증거로 사용하지 않음.
- 최대 카탈로그 1,000개, 화면 요소 300개. 점수는 보정된 확률이 아닌 휴리스틱.

프론트 `MenuScreenLinks`가 화면·좌표·카탈로그에 묶인 사용자 확인을 관리하고 `ScreenNavigator`와 `NativeOrderFlow`가 이를 공유한다. KotlinStructure는 수량을 포함한 기존 장바구니 행을 제외하고 OCR 이름을 미리 별칭으로 덮어쓰지 않는다.

프론트의 `ScreenMenuMatchingTest`에서 라이브러리 및 주문 흐름 회귀 테스트를 수행한다. 사진 OCR 정확도·실제 마이크 인식률은 이 문자열/좌표 테스트와 별도로 평가해야 한다.
