# Kotlin 0.2.5 키오스크 인식 QA 수정

## 재현 조건과 범위

사용자 QA: 실제 키오스크 2대에서 화면을 인식하지 못하고, 노트북 모의 키오스크의 커피 화면에서 “아메리카노 한 잔”을 주문하면 라테·주스 및 에이드·스무디 카테고리를 안내했다. 설치 버전은 Kotlin 0.2.5이다. 실제 촬영 이미지와 로그는 아직 없으므로 현장의 인식률을 측정한 결과는 아니다.

AI 저장소에만 적용하며 기존 안전 수정 브랜치 `fix/guidance-safety-20261006`의 `6b86532`를 기반으로 한다. 프론트 화면 구성·음성 모델 다운로드 메뉴·시작 버튼 위치 설명·카테고리 탐색 정책은 변경하지 않았다.

## 수정 내용

1. **M1 후보 검사:** 최고 점수 후보의 모서리가 잘려도 나머지 후보의 모서리 신뢰도·프레임 내부 좌표·볼록 사각형 조건을 확인한다. 유효 후보가 없으면 기존 위치 조정 안내를 유지한다. 감지 점수를 무조건 낮추거나 카메라 전체를 키오스크로 가정하지 않는다. Android와 Python에 반영했다.
2. **작은 글자 보존:** Android 영상 입력의 긴 변 제한을 1280→1920, 펼친 OCR 화면을 960→1440으로 조정했다. M1·M2 입력은 기존 640 텐서를 유지한다. 실제 정확도·지연 개선은 미측정이며 실기기 메모리·처리 시간 검증이 필요하다.
3. **메뉴 영역 연결:** ML Kit가 찾은 줄을 한 번씩 읽어 실제로 겹치는 메뉴·버튼 영역에 연결한다. 작은 가격 박스가 메뉴 이름을 가져가는 문제를 막는다. M2 밖의 글자도 `kind=text`의 읽기 전용 좌표와 문구로 보존한다.
4. **판독 불일치:** M3가 높은 점수로 다른 이름을 읽어도 ML Kit와 다르면 확정하지 않는다. 공백·통화 기호·쉼표 같은 표기 차이만 정규화한다. 미확인 문구는 보존하되 `uncertain=true`로 반환한다. 점수는 정확도 확률이 아니다.
5. **카테고리 보류:** 읽지 못한 메뉴 카드가 있거나 가격 근처 상품 글자가 M2 영역과 연결되지 않으면 탭과 다음 페이지 버튼을 미확인으로 반환한다. 기존 앱의 `readable` 검사로 임의 탐색을 보류한다. 확실히 읽은 메뉴 버튼은 계속 선택할 수 있다.
6. **읽기와 누름 구분:** OCR 글자 영역을 물리 메뉴 버튼으로 승격하지 않는다. AI 목표 지정은 `text`·`price`를 거부한다. 이름만 읽혔고 버튼은 불명확하면 재확인 흐름으로 이어진다.

## 추가 응답 필드

`structure`의 기존 필드는 유지하며 다음 선택 필드를 추가한다.

```json
{
  "recognition_status": "menu_ocr_incomplete",
  "recognition_diagnostics": {
    "ocr_lines": 12,
    "unassigned_lines": 3,
    "unconfirmed_menu_regions": 1,
    "category_navigation_blocked": true
  }
}
```

상태는 `read`, `no_text`, `menu_ocr_incomplete`이다. 줄 개수는 정확도가 아니다. 기존 앱은 새 진단 필드를 무시해도 `uncertain`·`conf_ocr` 계약으로 보류한다. 진단 화면 설명은 프론트 후속 작업이다.

## 검증

- AI JVM 16개: 아메리카노/라테/스무디 오판, 저신뢰도, 메뉴·가격 영역, 읽기 전용 좌표, M1 후보·비정상 값.
- Python 16개: 새 후보 검사 4개, 기존 좌표 검사 3개, 기존 안전 파이프라인 9개.
- 기존 Kotlin 앱 JVM 146개: 프론트 소스를 바꾸지 않고 수정 AI와 연동해 통과.
- Android 2개: 실제 ML Kit·M3 모델로 생성한 한국어 메뉴를 읽어 확인 상태·카드 누락·카테고리 보류를 검사. 실제 키오스크나 촬영한 노트북이 아닌 합성 이미지다.
- release APK·AAR 빌드. 해시·서명·카메라 검증 범위는 `kiosk-qa-validation-20261013.json`에 기록한다.

형제 프론트의 Gradle 루트에서 검사한다.

```powershell

.\gradlew.bat :sonkkeut-native:connectedDebugAndroidTest
```

Python은 AI 저장소에서 실행한다.


## 테스트 APK와 전달

프론트는 `native/kotlin-20261005`의 `2d8ed49` 그대로 사용하고, 형제 AI 폴더를 `fix/kiosk-qa-20261013`으로 연결해 기존 `:app:assembleRelease`로 빌드한다. 앱 UI·버전 이름 0.2.5·versionCode 15와 개발용 업데이트 서명을 유지한다. 수정 APK는 `sonkkeut-kotlin-0.2.5-ai-qa-20261013.apk`로 일반 0.2.5와 파일명·해시를 구분한다.

프론트 팀은 이 AI 브랜치를 연결해 재빌드하거나 제공 AAR의 모델·JNI·전이 의존성을 함께 확인한다. AAR만 추가하면 모든 의존성이 자동 포함되는 것은 아니다. 현재 Gradle 모듈 연결이 재현에 적합하다.

## 실물 재검증과 남은 제한

같은 기기·같은 화면으로 재테스트해야 한다. 두 OCR이 같은 오답을 내거나 M1이 유효 후보를 전혀 내지 않는 문제는 남는다. 가중치는 재학습하지 않았다. 입력 촬영 이미지 없이 실제 인식률이나 완전 해결을 선언하지 않는다.

화면 테두리와 메뉴가 함께 나온 촬영 이미지, 기기·앱 버전, 인식 문구·신뢰도·진단 필드를 확보해 탐지와 OCR 실패를 분리한다. 개인정보·결제 정보를 포함한 영상은 저장소에 올리지 않는다. 실제 실패 데이터에 따라 학습 데이터 보강·재학습을 진행한다.

프론트의 순차 카테고리 탐색은 남아 있다. 충분히 읽힌 화면에서 목표가 없으면 기존 탐색을 사용한다. 모든 카테고리 이동을 메뉴 분류에 근거하도록 바꾸려면 프론트의 별도 수정이 필요하다.
